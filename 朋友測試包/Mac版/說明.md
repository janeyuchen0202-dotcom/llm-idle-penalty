# Mac 版閒置測試（2026-10-19）

> 為了測使用者自己的 M1 Pro MacBook Pro（16 GB）。電腦在別的房間，由使用者的妹妹單機執行，不用搬東西。
> 給執行的人看的步驟：給執行的人的步驟.txt。要傳的只有 mac_idle_test.sh 一個檔（第二版 SHA-256 `37c2ad95…`；第一版 `aa83f237…` 另存在 原始碼/）。
> **10/23 發現：需要 macOS 26**。llama.cpp b9549 的 Mac 版是為 macOS 26.0 編譯的（libggml-metal 用到 macOS 15 才有的 `MTLResidencySetDescriptor`）。M1 Pro 的系統比較舊，伺服器一啟動就停（dyld: Symbol not found），在「確認模型能不能全部放進 GPU」那一步就結束，沒有量到任何東西。M1 Air 跑得動是因為它是 macOS 26.3.1。腳本本身沒有問題，也不是遠端控制造成的

## 為什麼做（10/19 決定）

「沒有代價」的那一組只有 2 台 Apple（M1 Air、M4 Air），又找不到 AMD、Intel 顯示卡。這組多一台，比 NVIDIA 多一台有價值。M1 Pro 的晶片等級不同，而且有風扇。

## 流程（和朋友測試包的 GPU 測試相同）

- 每輪重開伺服器，暖機 3 個請求
- 閒置 0、2、3、5、8 秒各 3 個請求為一個區塊，順序打亂，每輪 4 個區塊（60 個請求），共 5 輪
- 第 5 輪不記錄 GPU 狀態，當對照
- 工作負載和 Windows 版 GPU 測試相同：838 token prompt、128 token 輸出（提示詞內容逐字相同）
- 伺服器參數：`-c 4096 --parallel 1 -t 4 --cache-ram 0 -ngl all`（Mac 只有一個 GPU，不用指定裝置）
- 不算的輪自動補跑，最多 3 輪；判定條件和排除規則相同：沒插電、請求失敗、等待時 CPU 超過 30%、等待時 GPU 超過 10%、睡著或卡住
- 結果的格式和 Windows 版相同（requests.csv、run_info.json），analyze_friend.py 可以直接分析

## 和 Windows 版不同的地方

| 項目 | Windows 版 | Mac 版 |
|---|---|---|
| 防睡眠 | SetThreadExecutionState | `caffeinate -dims`（螢幕也保持亮著，和 10/8 測 M1 Air 時相同） |
| 插電 | GetSystemPowerStatus | `pmset -g batt` |
| 等待期間的 CPU | 每段等待前後讀 GetSystemTimes | `top` 每秒一筆，取整段落在等待裡的取樣 |
| 等待期間的 GPU | nvidia-smi 或 Windows 的 GPU 3D 使用率 | `ioreg` 的 "Device Utilization %"，每 0.5 秒一筆（不需要系統管理員密碼） |
| 時脈、P-state、功耗 | nvidia-smi | 沒有（要 sudo powermetrics，不做） |
| 模型放置 | 開始前確認層數＋每輪的顯示卡記憶體 | 開始前確認層數；每輪記成「未知」，分析時用服務時間檢查 |
| 執行環境 | 包裡附的 Python | 下載免安裝的 Python 3.12.14 |

## 做過的測試（10/19，在使用者的 Windows 筆電上）

1. 解析和遮個資：用 Mac 指令的範例輸出測 top、ioreg、system_profiler 的序號，再測路徑和名稱的遮法，全部通過
2. 主程式：用 Windows 的 llama-server 跑 1 輪 15 個請求，流程、輸出格式、版本紀錄都正常，analyze_friend.py 讀得了
3. 外層啟動檔：用替身指令假裝成 Mac（晶片、插電、磁碟、caffeinate），從頭跑到尾：檢查、核對三個檔、寫出主程式、啟動、打包，都正常
4. 下載：用真的 curl 下載 llama.cpp，核對成功；第二次自動跳過；雜湊值不對時會刪檔並停止
5. 發現並修正的問題：
   - Python 壓縮檔裡的 python3 是捷徑，改成直接用 python3.12
   - 自己指定的路徑寫法不同時會漏遮，改成兩種斜線的寫法都遮
   - 抓不到晶片名稱時會出現「GPU GPU」，已修正

**10/19 第一次在真的 Mac 上跑（M1 MacBook Air、macOS 26.3.1，08:22–09:36）：成功。**

## 第二版（2026-10-19b，SHA-256 `37c2ad95…`；第一版另存在 原始碼/mac_idle_test_v1_20261019.sh）

使用者指出「權限可以跟我要」：第一版為了不用密碼，沒有記錄溫度和頻率，所以 M1 閒置後反而變快的原因只能推論。第二版加了：

- **powermetrics（要登入密碼一次，可以跳過）**：每 0.5 秒記錄 GPU 頻率、GPU 和 CPU 的耗電、過熱的程度（thermal pressure），存成 powermetrics.txt 一起打包
  - 輸入密碼後，背景每 50 秒續一次權限，powermetrics 才能跑完整段測試
  - 不管怎麼結束（跑完、出錯、按 Ctrl+C、關掉視窗），都會把權限續期和 powermetrics 一起關掉
- **電池低於 80% 時提醒先充電**（第一版 M1 Air 是 9% 邊充電邊跑）
- 測試：用 sudo、powermetrics 的替身在模擬環境從頭跑一次，紀錄有一起打包、背景程式都有關掉；電量提醒在 9%、79%、80%、100% 都正確
